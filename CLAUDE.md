# Good Karma — контекст проекта

Продакшн-версия сайта паназиатского кафе. Переехали с прототипа
(один `index.html`, vanilla JS, JSON-сид) на Next.js 14 + TypeScript +
Tailwind + Prisma/PostgreSQL.

Общайся по-русски.

## Стек

- Next.js 14 (App Router), React 18, TypeScript strict
- Tailwind CSS 3.4
- Prisma + PostgreSQL (хостится в Supabase, регион Ирландия)
- Zustand для корзины (localStorage, ключ `gk_cart`)
- Zod для валидации серверных экшенов

## Команды

```bash
npm run dev              # запуск
npm run db:seed          # засеять/обновить данные (идемпотентно)
npx prisma db push       # применить схему к базе
npm run check:delivery   # проверка границ зон доставки
npx tsc --noEmit         # типы
npx eslint src --ext .ts,.tsx
```

## Важные особенности окружения (не потерять)

**Порт базы 5432, не 6543.** Supabase выдаёт строку с пулером на порту
6543 — на машине владельца проекта он зависает намертво (проверяли: TCP
проходит, но соединение не устанавливается). Прямое подключение на 5432
работает мгновенно. Если в `.env` окажется 6543 — миграции будут виснуть.

**Пароль базы без спецсимволов.** `?`, `/`, `@`, `#` в пароле ломают
парсинг URL подключения (ошибка P1013 «invalid port number»).

**`npx prisma validate` и `generate` работают** и в песочнице Codex, и в
песочнице Claude (проверено 2026-09-14 обеими сторонами) — старое
предупреждение об недоступности `binaries.prisma.sh` больше не актуально,
не переносите его в новые инструкции. Если `tsc` вдруг снова покажет
«Module '@prisma/client' has no exported member ...» — сначала прогоните
`npx prisma generate`, это почти всегда просто рассинхронизированный клиент,
а не реальная ошибка типов.

**Пул соединений Supabase маленький (`pool_size: 15`).** Если Claude и
Codex работают одновременно (или просто оставлен запущенным `npm run dev`
во время `npm run build`), сборка/скрипты могут упасть с
`FATAL: (EMAXCONNSESSION) max clients reached` — это исчерпание пула, а не
баг в коде. Перед `npm run build` останавливайте лишние `npm run dev` /
скрипты с БД, при повторном сбое — просто подождать и повторить.

**После правки `schema.prisma` на Windows сначала остановите `npm run dev`.**
`npx prisma db push`/`generate` перезаписывает
`node_modules\.prisma\client\query_engine-windows.dll.node`, а этот файл
залочен, пока его держит открытым работающий dev-сервер — падает с
`EPERM: operation not permitted, rename ...`. Схема в базу при этом уже
применяется (`db push` успевает), не хватает только регенерации клиента —
после остановки сервера просто повторите `npx prisma generate`.

## Дизайн-система

**Цвета — RGB-тройки, не hex.** В `globals.css` все токены заданы как
`--plum: 126 85 128`, а в `tailwind.config.ts` обёрнуты в
`rgb(var(--plum) / <alpha-value>)`. Это обязательное требование Tailwind v3:
с hex-значениями классы вида `border-plum/30` **молча исчезают** из
собранного CSS. Проверяли реальной сборкой.

Палитра: warm ivory `#F5F0E8`, cream `#FBF8F2`, beige `#EDE5D9`,
lavender `#E9E0EE`, mint `#DFEAE3`, blush `#F0DDE1`, deep plum `#493044`,
cherry `#9A536E`, gold `#B49A68`. Чистый белый не использовать.

**Шрифты:** везде Montserrat (класс `font-sans`, шрифт интерфейса и
заголовков). Editorial-засечный Cormorant Garamond (`font-serif`) убрали —
раньше был на акциях и Karma Club, теперь эти страницы используют те же
шрифты, что главная и меню.

**Тема:** атрибут `data-theme` на `<html>`, ключ `gk_theme` в localStorage,
выставляется инлайн-скриптом до отрисовки (`ThemeScript.tsx`).

## Ассеты

Все локальные картинки лежат в `public/assets`, пути — **только** через
реестр `src/lib/assets.ts`. Base64 не использовать. У исходных маскотов
были подписи внизу («Кот 3») — они срезаны.

Анимированные WebP-подложки подключать через `BackgroundFootage.tsx` —
он сам скрывает их при `prefers-reduced-motion`, убирает из tab-порядка
и не даёт перехватывать клики. Не больше 1–2 анимированных слоёв на секцию.

## Ключевые архитектурные решения

**Цены — целые копейки** (`priceCents`), не рубли с плавающей точкой.

**Расчёт заказа только на сервере** (`src/server/pricing.ts`). Клиент
присылает лишь «что и сколько» — цены, скидки и доставку сервер берёт из
базы и считает заново. В прототипе скидка считалась в браузере, и её можно
было подменить через консоль. Это принципиально, не откатывать.

**Зоны доставки** (`src/lib/delivery.ts`) — гаверсинус от координат кафе,
5 зон: 250+100×i ₽, бесплатно от 1500+1000×i ₽, дальше 20 км нет доставки.
Границы включающие снизу: ровно 4 км — ещё первая зона, 4.1 — вторая.
Покрыто проверкой `npm run check:delivery`.

**Скидки за самовывоз нет.** Была −10%, отменена везде: в формуле, текстах,
акциях, админке. Самовывоз остаётся способом получения без скидки.

**У `Promotion.type = FIXED` пока нет реальной фиксированной скидки.**
`src/server/pricing.ts` считает скидку только как `discountPct` от суммы
заказа — поля для суммы в копейках у фиксированного типа нет, `type` в
расчёте вообще не читается. Admin-форма акции честно предупреждает об этом
при выборе «Фиксированный», но само поведение не переопределено — если
понадобится настоящая фиксированная скидка, нужно добавить `discountCents`
в схему и ветвление по `type` в `pricing.ts`.

**Трекинг без обратного отсчёта.** Не показываем ETA и курьера-персонажа.
Только статусы (Заказ принят → Готовится → Передан в доставку →
Доставляется) и кнопка «Узнать о заказе» на `DELIVERY_PHONE` или
`DELIVERY_TRACKING_URL`.

## Что сделано

- Главная, `/menu`, `/menu/[id]`, `/product/[slug]`, `/promotions`,
  `/karma-club`, `/checkout`, `/order/[number]`, `/profile`, `/wok-builder`
- Корзина с добавками (одно блюдо с разными добавками = разные строки)
- Оформление заказа с геолокацией и расчётом зоны, запись заказа в БД
- Акции: editorial-флагман + две разнохарактерные карточки, промокод
  копируется в буфер и применяется к корзине
- Karma Club: панель статуса, уровни (Seed 0 / Blossom 500 / Moon 1200 /
  Karma 2500), награды с состояниями LOCKED / AVAILABLE / CLAIMED,
  ближайшая награда, история. Всё считается из одного числа баллов.
  Демо-версия на публичной странице явно подписана («Демонстрация клуба» +
  сворачиваемый блок), чтобы не путалась с настоящей картой в профиле.
- Профиль: вход по телефону с одноразовым кодом через Telegram-бота
  (`TELEGRAM_BOT_TOKEN`), не SMS — бесплатно и доставка мгновенная. Бот не
  может написать первым: для нового номера сайт даёт deep-link
  `t.me/<bot>?start=<телефон>`, человек жмёт Start, сайт находит апдейт через
  `getUpdates` (не вебхук — нет публичного HTTPS) и сохраняет `TelegramLink`
  phone→chatId; дальше код шлётся сразу без этого шага. Карта Karma Club,
  история заказов, награды, адреса. После входа сервер выдаёт подписанную
  `httpOnly` cookie (`gk_customer_session`, `CUSTOMER_SESSION_SECRET`) — все
  действия в профиле берут `userId` из неё, не из клиента, `localStorage`
  (`gk_identity`) только для UI
- Конструктор вока (`/wok-builder`): основа → белок → соус, три шага
- Мобильная нижняя навигация (`MobileNav`, показывается только `< md`)
- Админка, фаза 1: JWT-аутентификация, CRUD товаров и прямая загрузка
  изображений в S3-совместимое хранилище по presigned PUT URL
- Админка, фаза 2: CRUD категорий и `CategoryMeta`, акций, уровней/наград
  Karma Club и боевых зон доставки
- Админка: CRUD ингредиентов конструктора вока (основы, белки, соусы)
- Админка заказов: очередь, история, детальная карточка и смена статусов
  заказа/оплаты без редактирования зафиксированного состава и сумм
- Админка: роли (`OWNER`/`STAFF`) и управление командой на `/admin/team` —
  создание администратора, смена роли, удаление. Роль ограничивает доступ
  только к этому разделу, остальная админка одинакова для обеих ролей.
  Нельзя удалить/разжаловать последнего OWNER или удалить самого себя.

## Чего ещё нет

Реальная оплата (ЮKassa + онлайн-касса по 54-ФЗ), выход со всех устройств
сразу (сейчас сессия покупателя — одна долгоживущая cookie на устройство,
отозвать конкретную удалённо нельзя), конструктор пиццы на PNG
из `public/assets/pizza`, миры категорий.

## Юридическое (не забыть перед запуском)

С 1 июля 2025 персональные данные граждан РФ нельзя собирать в базы за
пределами России (152-ФЗ, ст. 18 ч. 5). Сейчас база в Ирландии — для
разработки нормально, перед боевым запуском переезжать на российский
хостинг (Yandex Cloud, Selectel, VK Cloud — или reg.ru, целевой хостинг
по последнему обсуждению). Персональные данные в схеме: `User.phone`,
`User.name`, `Address.*`, `AdminUser.email`, `AdminUser.name`.

## Правила работы с кодом

- Не переписывать работающее без необходимости
- Комментарии в коде — по-русски, объясняют «почему», а не «что»
- Серверные компоненты по умолчанию; `"use client"` только там, где нужна
  интерактивность
- Перед завершением задачи прогонять `npx eslint` и `npx tsc --noEmit`
