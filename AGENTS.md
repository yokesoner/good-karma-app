# Good Karma — контекст проекта

Продакшн-версия сайта паназиатского кафе. Переехали с прототипа
(один `index.html`, vanilla JS, JSON-сид) на Next.js 14 + TypeScript +
Tailwind + Prisma/PostgreSQL.

Общайся по-русски.

## Стек

- Next.js 14 (App Router), React 18, TypeScript strict
- Tailwind CSS 3.4
- Prisma + PostgreSQL (хостится в Supabase, регион Ирландия)
- Zustand для корзины (localStorage, ключ `gk_cart`)
- Zod для валидации серверных экшенов

## Команды

```bash
npm run dev              # запуск
npm run db:seed          # засеять/обновить данные (идемпотентно)
npx prisma db push       # применить схему к базе
npm run check:delivery   # проверка границ зон доставки
npx tsc --noEmit         # типы
npx eslint src --ext .ts,.tsx
```

## Важные особенности окружения (не потерять)

**Локальная база для разработки на этой машине (с 2026-09-29).** Supabase
отстал от схемы (там ещё старые колонки `perk*` у `karma_levels`, а новых
`discountPct/discountsPerWeek` нет), и пароль в `.env` к нему перестал
подходить. Поэтому `npm run dev` ходит в локальный PostgreSQL 17:
бинарники в `D:\dev\pgsql`, данные в `D:\dev\pgdata`, порт **5433**, база
`goodkarma`. Строка подключения — в `.env.development.local` (в `.gitignore`;
Next в dev-режиме берёт его приоритетнее `.env`, а `npm run build/start` —
по-прежнему `.env`). Там же логин тестового админа локальной базы.
Сервер БД не служба Windows — после перезагрузки ПК запустить вручную:
`D:\dev\pgsql\bin\pg_ctl.exe -D D:\dev\pgdata -l D:\dev\pgdata\server.log start`.
Prisma CLI читает только `.env`, поэтому для `db push`/`db:seed` в локальную
базу передавайте `DATABASE_URL`/`DIRECT_URL` из `.env.development.local`
переменными окружения. Supabase перед использованием нужно привести к
текущей схеме (`prisma db push` удалит устаревшие `perk*`).
**Порт базы 5432, не 6543.** Supabase выдаёт строку с пулером на порту
6543 — на машине владельца проекта он зависает намертво (проверяли: TCP
проходит, но соединение не устанавливается). Прямое подключение на 5432
работает мгновенно. Если в `.env` окажется 6543 — миграции будут виснуть.

**Пароль базы без спецсимволов.** `?`, `/`, `@`, `#` в пароле ломают
парсинг URL подключения (ошибка P1013 «invalid port number»).

**`npx prisma validate` и `generate` работают** и в песочнице Codex, и в
песочнице Claude (проверено 2026-09-14 обеими сторонами) — старое
предупреждение об недоступности `binaries.prisma.sh` больше не актуально,
не переносите его в новые инструкции. Если `tsc` вдруг снова покажет
«Module '@prisma/client' has no exported member ...» — сначала прогоните
`npx prisma generate`, это почти всегда просто рассинхронизированный клиент,
а не реальная ошибка типов.

**Пул соединений Supabase маленький (`pool_size: 15`).** Если Claude и
Codex работают одновременно (или просто оставлен запущенным `npm run dev`
во время `npm run build`), сборка/скрипты могут упасть с
`FATAL: (EMAXCONNSESSION) max clients reached` — это исчерпание пула, а не
баг в коде. Перед `npm run build` останавливайте лишние `npm run dev` /
скрипты с БД, при повторном сбое — просто подождать и повторить.

Настоящая причина найдена 2026-09-16: `next build` параллельно
пререндерит статические страницы в нескольких воркер-процессах, и каждый
открывает свой `PrismaClient` со своим пулом — при обычных настройках это
надёжно упирается в лимит 15 даже без Codex рядом (сборка падала на одних
и тех же страницах `/`, `/promotions`, `/wok-builder` два раза подряд).
Фикс: добавить `?connection_limit=2` в конец `DATABASE_URL` и `DIRECT_URL`
в `.env` — ограничивает пул каждого воркера, сборка становится стабильной.
На боевой базе (не Supabase-пулер с лимитом 15) это не обязательно, но не
мешает — оставить как разумный дефолт.

**После правки `schema.prisma` на Windows сначала остановите `npm run dev`.**
`npx prisma db push`/`generate` перезаписывает
`node_modules\.prisma\client\query_engine-windows.dll.node`, а этот файл
залочен, пока его держит открытым работающий dev-сервер — падает с
`EPERM: operation not permitted, rename ...`. Схема в базу при этом уже
применяется (`db push` успевает), не хватает только регенерации клиента —
после остановки сервера просто повторите `npx prisma generate`.

**На Mac, если проект лежит внутри другой папки со своим старым
`eslint.config.mjs` (например, заброшенный ранний прототип на
`create-next-app`), `npx eslint`/`npm run lint` может тихо подхватить
flat-config того родителя вместо `.eslintrc.json` этого проекта и упасть
на `@typescript-eslint/no-unused-expressions` с
`Cannot read properties of undefined (reading 'allowShortCircuit')`, либо
отказаться понимать `--ext` («You're using eslint.config.js»). Это не
баг в коде — ESLint 8 иногда обнаруживает `eslint.config.*` у предка и
переключается в flat-режим. Лечится принудительным classic-режимом:
`ESLINT_USE_FLAT_CONFIG=false npm run lint`.

## Дизайн-система

**Цвета — RGB-тройки, не hex.** В `globals.css` все токены заданы как
`--plum: 126 85 128`, а в `tailwind.config.ts` обёрнуты в
`rgb(var(--plum) / <alpha-value>)`. Это обязательное требование Tailwind v3:
с hex-значениями классы вида `border-plum/30` **молча исчезают** из
собранного CSS. Проверяли реальной сборкой.

Палитра: warm ivory `#F5F0E8`, cream `#FBF8F2`, beige `#EDE5D9`,
lavender `#E9E0EE`, mint `#DFEAE3`, blush `#F0DDE1`, deep plum `#493044`,
cherry `#9A536E`, gold `#B49A68`. Чистый белый не использовать.

**Шрифты:** везде Montserrat (класс `font-sans`, шрифт интерфейса и
заголовков). Editorial-засечный Cormorant Garamond (`font-serif`) убрали —
раньше был на акциях и Karma Club, теперь эти страницы используют те же
шрифты, что главная и меню.
**Шкала кегля — нижние ступени токенами, не произвольными px.** Мельче
10px на сайте ничего нет: `text-micro` (10px) — подписи капсом с
трекингом, бейджи, чипы, счётчики; `text-caption` (11px) — мелкий обычный
текст. Заданы в `tailwind.config.ts` (`fontSize`). Раньше было ~90 мест с
`text-[7.5px]`…`text-[9.5px]` — на телефоне нечитаемо. Новые `text-[8px]`
и т.п. не вводить; адаптивные `md:text-[9px]` поверх `text-micro` тоже
(они уменьшали бы текст обратно на больших экранах).

**Тема:** атрибут `data-theme` на `<html>`, ключ `gk_theme` в localStorage,
выставляется инлайн-скриптом до отрисовки (`ThemeScript.tsx`).

## Ассеты

Все локальные картинки лежат в `public/assets`, пути — **только** через
реестр `src/lib/assets.ts`. Base64 не использовать. У исходных маскотов
были подписи внизу («Кот 3») — они срезаны.

Анимированные WebP-подложки подключать через `BackgroundFootage.tsx` —
он сам скрывает их при `prefers-reduced-motion`, убирает из tab-порядка
и не даёт перехватывать клики. Не больше 1–2 анимированных слоёв на секцию.
Пропа `priority` у него нет намеренно: декор всегда грузится лениво и не
предзагружается, чтобы не конкурировать за сеть с LCP-фотографией экрана.

## Ключевые архитектурные решения

**Цены — целые копейки** (`priceCents`), не рубли с плавающей точкой.

**Расчёт заказа только на сервере** (`src/server/pricing.ts`). Клиент
присылает лишь «что и сколько» — цены, скидки и доставку сервер берёт из
базы и считает заново. В прототипе скидка считалась в браузере, и её можно
было подменить через консоль. Это принципиально, не откатывать.

**Зоны доставки** (`src/lib/delivery.ts`) — гаверсинус от координат кафе
(константа `CAFE`/`CAFE_ADDRESS`, реальный адрес — Ставрополь, переулок
Крупской, 29/1), 5 зон: 250+100×i ₽, бесплатно от 1500+1000×i ₽, дальше
20 км нет доставки. Границы включающие снизу: ровно 4 км — ещё первая
зона, 4.1 — вторая. Покрыто проверкой `npm run check:delivery`. Сами
радиусы (`maxDistanceKm`), цены и порог бесплатной доставки редактируются
в `/admin/delivery-zones`.

**Адрес доставки проверяется геокодером, а не только геолокацией.**
Раньше расстояние считалось лишь из `lat/lng`, которые прислал браузер
(кнопка «Определить местоположение») — при ручном вводе адреса проверки
не было вообще, а `lat/lng` как значения от клиента можно было подменить
в devtools (например, прислать координаты самого кафе и получить 0 км
откуда угодно). Теперь единственный источник — текст адреса:
`src/lib/geocoder.ts` геокодирует его на сервере (`resolveDeliveryAddress`
в `src/server/actions.ts`, используется и в `quoteOrder`, и в `placeOrder` —
клиентский расчёт при вводе адреса только для UX, решает всегда сервер),
проверяет город (`CAFE_CITY`, «доставляем только по Ставрополю») и
расстояние. Кнопка геолокации теперь делает обратное геокодирование
(координаты → текст) и просто подставляет его в поле адреса — единый путь
для ручного ввода и автоопределения.

Геокодер — бесплатный OpenStreetMap/Nominatim, без API-ключа (сознательное
решение — платные сервисы Яндекса не подключаем). У Nominatim жёсткая
политика использования (~1 запрос/сек на IP, обязательный User-Agent) —
`geocoder.ts` держит in-memory кэш на 5 минут и сериализованную очередь
запросов с паузой между ними. При заметном росте заказов этого может не
хватить — тогда либо платный геокодер, либо свой инстанс Nominatim.
`<CafeMap>` (`src/components/CafeMap.tsx`) — виджет Яндекс.Карт
(`map-widget/v1`, обычная ссылка «поделиться → встроить», без API-ключа и
регистрации — владелец попросил вернуть именно Яндекс для отображения,
это отдельная вещь от геокодера выше). Показывает адрес кафе на главной
(в `Footer`) и на самовывозе в чекауте. Виджет интерактивный и грузится не
мгновенно (в отличие от лёгкого статичного OSM-эмбеда, который был здесь
раньше) — это нормально, не баг.

**Скидки за самовывоз нет.** Была −10%, отменена везде: в формуле, текстах,
акциях, админке. Самовывоз остаётся способом получения без скидки.

**У `Promotion.type = FIXED` пока нет реальной фиксированной скидки.**
`src/server/pricing.ts` считает скидку только как `discountPct` от суммы
заказа — поля для суммы в копейках у фиксированного типа нет, `type` в
расчёте вообще не читается. Admin-форма акции честно предупреждает об этом
при выборе «Фиксированный», но само поведение не переопределено — если
понадобится настоящая фиксированная скидка, нужно добавить `discountCents`
в схему и ветвление по `type` в `pricing.ts`.

**Трекинг без обратного отсчёта.** Не показываем ETA и курьера-персонажа.
Только статусы (Заказ принят → Готовится → Передан в доставку →
Доставляется) и кнопка «Узнать о заказе» на `DELIVERY_PHONE` или
`DELIVERY_TRACKING_URL`.

**`/order/[number]` защищён доступом по номеру+телефону, не открыт всем.**
Номера заказов последовательные (`GK-00001`, ...) — без этого страница
читалась бы перебором URL (чужой адрес доставки, состав). Доступ — подписанная
cookie (`src/lib/orderAccess.ts`): выдаётся автоматически после своего же
чекаута (`grantOrderAccess` в `placeOrder`) или после подтверждения телефона
через `trackOrder` (используется и инлайн-гейтом на самой странице, и
публичной формой на `/track`). Полный телефон + точный номер — уже
достаточная защита от перебора, отдельный рейт-лимитер не заводили.

## Что сделано

- Главная, `/menu`, `/menu/[id]`, `/product/[slug]`, `/promotions`,
  `/karma-club`, `/checkout`, `/order/[number]`, `/track`, `/profile`,
  `/wok-builder` — `/track` даёт отследить заказ по номеру+телефону без
  входа в профиль
- Корзина с добавками (одно блюдо с разными добавками = разные строки)
- Оформление заказа с геолокацией и расчётом зоны, запись заказа в БД
- Акции: редакционная шапка + талоны на каждую акцию (подробнее ниже,
  «Акции, второй заход»), промокод
  копируется в буфер и применяется к корзине. Редакционный блок (заголовок,
  текст, фон) редактируется из админки (`PromoHeroBanner`, синглтон-запись);
  у карточек — своя картинка (загрузка на диск сервера, приоритетнее фото товара) и выбор
  фона из фиксированного набора пресетов (`src/lib/promoBackgrounds.ts`), не
  свободный цвет, чтобы не разъезжалась палитра
- Karma Club: панель статуса, уровни (Seed 0 / Blossom 500 / Moon 1200 /
  Karma 2500), ближайшая награда, история. Всё считается из одного числа
  баллов. Демо-версия на публичной странице явно подписана («Демонстрация
  клуба» + сворачиваемый блок), чтобы не путалась с настоящей картой в
  профиле — у неё свой `rewardState`/`RewardState` (`src/lib/karma.ts`,
  LOCKED/AVAILABLE/CLAIMED) для иллюстрации, реальный обмен его не использует.

  **Награды — конкретные товары, не абстрактный текст, и переиспользуемые.**
  У каждой награды (`/admin/karma-club`) админ привязывает один или
  несколько товаров через `KarmaRewardProduct` (join-таблица, тот же
  паттерн, что `ProductAddonGroup`). Без единого товара награду нельзя
  обменять на сайте — список в админке честно показывает «Нет товаров —
  обменять нельзя». В `/profile` кнопка «Добавить в корзину» кладёт
  выбранный товар в `useCart()` как обычную строку корзины с `rewardId`
  (несколько привязанных товаров — сначала выбор одного); баллы **не
  списываются в момент клика** — это только добавление в корзину, списание
  происходит вместе с оформлением заказа (`resolveRewardLines` в
  `src/server/actions.ts`, используется и в `quoteOrder` для живого
  предпросмотра, и в `placeOrder` как финальное решение). Так подарок не
  сгорает, если гость передумал/забыл оформить заказ. Награда **не
  одноразовая** — доступность решает только текущий баланс (`data.points >=
  costPoints` в `ProfileView.tsx`), без постоянного «получено навсегда»:
  набрал баллы снова — можно получить тот же подарок ещё раз (сознательно
  отказались от разового ограничения — оно разочаровывало владельца).
  Требует сессию `/profile` (баллы принадлежат аутентифицированному
  профилю, не гостевому чекауту) — при оформлении сверяется, что телефон в
  форме заказа совпадает с профилем, иначе можно было бы потратить чужие
  баллы. Старый однократный `claimReward` (списание сразу при клике) убран.
- Профиль: вход по телефону с одноразовым кодом через Telegram-бота
  (`TELEGRAM_BOT_TOKEN`), не SMS — бесплатно и доставка мгновенная. Бот не
  может написать первым: для нового номера сайт даёт deep-link
  `t.me/<bot>?start=<телефон>`, человек жмёт Start, сайт находит апдейт через
  `getUpdates` (не вебхук — нет публичного HTTPS) и сохраняет `TelegramLink`
  phone→chatId; дальше код шлётся сразу без этого шага. Карта Karma Club,
  история заказов, награды, адреса. После входа сервер выдаёт подписанную
  `httpOnly` cookie (`gk_customer_session`, `CUSTOMER_SESSION_SECRET`) — все
  действия в профиле берут `userId` из неё, не из клиента, `localStorage`
  (`gk_identity`) только для UI
- Конструктор вока (`/wok-builder`): основа → белок → соус, три шага
- Мобильная нижняя навигация (`MobileNav`, показывается только `< md`)
- Служебные страницы `not-found.tsx` / `error.tsx` / `global-error.tsx` на
  общем `SystemPage`: чаша-кинцуги (`KintsugiBowl`) со сколом для 404 и
  золотым швом для сбоя. Ошибки БД внутри секций намеренно не ловим —
  статические страницы при сбое регенерации отдают последнюю удачную
  версию, а пойманная ошибка закешировала бы заглушку вместо меню
- Контакты кафе (телефон, почта, адрес) — одна точка `src/lib/contacts.ts`
- Акции (сентябрь 2026, второй заход). **Карусель на главной**
  (`HomePromotions` → `PromoCarousel`): формат «историй» — сегменты
  прогресса, свайп на нативном scroll-snap, автопрокрутка на CSS-анимации
  полоски (`animationend` листает, пауза — `animation-play-state`), стоит
  при наведении/фокусе/скрытой вкладке/вне экрана, нет при reduced motion,
  есть кнопка паузы (WCAG 2.2.2). **`/promotions` — талоны** (`PromoTicket`):
  линия отрыва — золотой шов, вырезы — CSS-маска, размер цифры скидки по
  container query; раскрывающиеся «Условия», печать-ханко `PromoStamp`,
  когда код уже в корзине. Любое число акций, пустое состояние есть.
  Админка: у `Promotion` поля `label` (метка — раньше выбиралась в коде по
  `code === "HAPPY20"`), `showOnHome` (в карусели), `sortOrder`. Единый
  серверный загрузчик витрины — `getStorefrontPromotions`
  (`src/server/storefrontPromotions.ts`). **Анонс вместо исчезновения:**
  `promoTiming` (`src/lib/promoSchedule.ts`) показывает «Идёт сейчас · до
  18:00» или «Начнётся · сегодня с 15:00» (анонс до 7 дней вперёд); у
  анонса промокод виден, но не применяется. Применимость при заказе
  по-прежнему решает только `isPromotionCurrentlyActive`. Главная —

## Правила работы с кодом

- Не переписывать работающее без необходимости
- Комментарии в коде — по-русски, объясняют «почему», а не «что»
- Серверные компоненты по умолчанию; `"use client"` только там, где нужна
  интерактивность
- Перед завершением задачи прогонять `npx eslint` и `npx tsc --noEmit`
