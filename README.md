# Good Karma — продакшн-версия

Переезд с прототипа (один `index.html`, vanilla JS, JSON-сид) на настоящее
приложение: Next.js 14 (App Router) + TypeScript + Tailwind + Prisma/PostgreSQL.

## Что сделано

**Фаза 1, часть первая — фундамент:**

- **`prisma/schema.prisma`** — полная модель данных: каталог, категории с их
  визуальными мирами, конструктор вока, промокоды (без скидки на самовывоз —
  она отменена и в схеме её нет), карма-клуб с журналом начислений (в
  прототипе баллы были просто числом, здесь — историей), зоны доставки,
  заказы с снэпшотом кастомной сборки блюда.
- **`prisma/seed.ts`** — переносит данные из `data/seed.json` (это ровно тот
  JSON, что лежал в `<script id="gk-seed">` прототипа) и `data/design-data.json`
  (то, что было захардкожено в JS-константах: `CAT_META`, `wokBases/Proteins/Sauces`,
  `karmaLevels`, `ADDON_SETS`, зоны доставки). Скрипт **идемпотентный** —
  перезапускать безопасно, данные обновятся, а не задублируются.
- **Дизайн-система** — все токены прототипа перенесены для обеих тем.
  Цвета хранятся как RGB-тройки (`126 85 128`, не `#7e5580`) — это
  обязательное требование Tailwind v3 для модификаторов прозрачности
  (`border-plum/30`), см. комментарий в `globals.css`.

**Фаза 1, часть вторая — страницы и корзина:**

- **Главная** (`/`) — Hero, меню с лентой категорий, акции, карма-клуб, футер.
- **Страница категории** (`/menu/[id]`) — с «визуальным миром» категории
  (фото, японская подпись, слоган из `CategoryMeta`).
- **Страница блюда** (`/product/[slug]`) — галерея, состав, КБЖУ, выбор
  добавок с пересчётом цены, динамические og-теги для превью в мессенджерах.
- **Корзина** — Zustand + localStorage (ключ `gk_cart`), панель со счётчиком
  в шапке, изменение количества, прогресс до бесплатной доставки.
- **Шапка** — навигация, переключатель темы, счётчик корзины.

**Фаза 1, часть третья — заказ:**

- **Чекаут** (`/checkout`) — способ получения, контакты, адрес с определением
  геопозиции, оплата, промокод. Итог **пересчитывается на сервере** при каждом
  изменении: цены блюд, добавок и скидка берутся из базы, а не из браузера.
  В прототипе скидка считалась в JS на клиенте — подменив её в консоли, можно
  было оформить заказ за любую сумму. Здесь клиент присылает только «что и
  сколько», всё остальное решает сервер (`src/server/pricing.ts`).
- **Зоны доставки** (`src/lib/delivery.ts`) — гаверсинус + пять зон, цена
  и порог бесплатной доставки зависят от расстояния. Логика вынесена отдельно
  и покрыта проверкой границ: `npm run check:delivery` (ровно 4 км — ещё первая
  зона, 4.1 — уже вторая; дальше 20 км доставки нет).
- **Страница заказа** (`/order/[number]`) — этапы без обратного отсчёта
  (сознательное решение из прототипа), состав, кнопка «Узнать о заказе»
  на телефон или внешнюю страницу через константу.
- Заказ пишется в базу вместе с позициями, добавками и начислением
  карма-баллов в журнал (`KarmaLedgerEntry`).

**Фаза 1, часть четвёртая — страницы и интерактив:**

- **Отдельные страницы** вместо якорей: `/menu` (весь каталог по категориям),
  `/promotions`, `/karma-club`, плюс уже были `/menu/[id]`, `/product/[slug]`,
  `/checkout`, `/order/[number]`. В шапке активный пункт подсвечивается.
- **Акции стали интерактивными**: кнопка промокода копирует его в буфер
  и сразу применяет к корзине — на чекауте поле уже заполнено. Промокод
  хранится в общем состоянии корзины.
- **Карма-клуб — калькулятор**: два ползунка (средний чек и число заказов
  в месяц) показывают, сколько баллов накопится за три месяца, до какого
  уровня это доведёт и на какую награду хватит.
- **Исправлена вёрстка флагманской акции**: классы раскладки передавались
  в декоративную обёртку `PromoFrame`, а не на контент — из-за этого две
  колонки схлопывались и фото падало под текст.

## Чего ещё нет

Авторизация по телефону (заказ создаётся по номеру без подтверждения кодом),
реальная оплата, конструктор вока, профиль, админка.

## Важное ограничение этой сессии

Я собрал схему и код, но **не смог прогнать `npx prisma validate` /
`generate` / `migrate`** — песочница, в которой я работаю, не имеет доступа
к `binaries.prisma.sh` (домен, с которого Prisma качает нативный движок), это
ограничение только моей текущей среды, не вашей. Схему я проверил вручную —
все связи двусторонние, композитные ключи на местах — но первое, что стоит
сделать на вашей машине:

```bash
npm install
cp .env.example .env
docker compose up -d          # локальный Postgres
npx prisma validate           # обязательно прогнать первым
npx prisma migrate dev --name init
npm run db:seed
npm run dev
```

Если `prisma validate` найдёт что-то — это единственное место, где я не
могу дать стопроцентную гарантию без живого прогона.

## Дальше по фазам (из прошлого обсуждения)

- **Фаза 1 (продолжение)** — страницы `/menu/[category]`, карточка товара,
  корзина как настоящее серверное состояние (сейчас в прототипе скидка по
  промокоду считается в браузере — это дыра, которую нужно закрыть на сервере
  до какой-либо реальной оплаты).
- **Фаза 2** — ЮKassa + онлайн-касса (54-ФЗ, обязательно для приёма оплаты),
  Яндекс.Карты/Геокодер вместо формулы гаверсинуса.
- **Фаза 3** — конструктор вока и добавки к блюдам как записи в БД
  (`WokBase/Protein/Sauce`, `AddonGroup/Addon` уже в схеме), карма-клуб
  с реальным начислением через `KarmaLedgerEntry`.
- **Фаза 4** — трекинг заказа в реальном времени (WebSocket/SSE), SMS или
  Telegram-бот на смену статуса.
- **Фаза 5** — настоящая фотосъёмка вместо Unsplash, перенос картинок в
  S3-совместимое хранилище, Яндекс.Метрика, Playwright-тесты (24 сценария
  из прототипа — готовый чек-лист приёмки).

## Структура

```
prisma/
  schema.prisma      — модель данных
  seed.ts            — перенос данных из прототипа в БД
data/
  seed.json          — снятый слепок текущего каталога прототипа
  design-data.json   — категории/вок/карма/зоны, которые в прототипе жили в JS
src/
  app/
    layout.tsx        — шрифт, тема, метаданные
    page.tsx          — главная (реальный запрос в БД)
    globals.css        — токены дизайн-системы
  components/
    ProductCard.tsx
    CategoryStrip.tsx
    ThemeScript.tsx
  lib/
    db.ts             — синглтон Prisma-клиента
    money.ts           — форматирование цен (копейки → ₽)
```
