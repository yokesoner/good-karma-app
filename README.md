# Good Karma — продакшн-версия

Переезд с прототипа (один `index.html`, vanilla JS, JSON-сид) на настоящее
приложение: Next.js 14 (App Router) + TypeScript + Tailwind + Prisma/PostgreSQL.

## Что сделано

**Фаза 1, часть первая — фундамент:**

- **`prisma/schema.prisma`** — полная модель данных: каталог, категории с их
  визуальными мирами, конструктор вока, промокоды (без скидки на самовывоз —
  она отменена и в схеме её нет), карма-клуб с журналом начислений (в
  прототипе баллы были просто числом, здесь — историей), зоны доставки,
  заказы с снэпшотом кастомной сборки блюда.
- **`prisma/seed.ts`** — переносит данные из `data/seed.json` (это ровно тот
  JSON, что лежал в `<script id="gk-seed">` прототипа) и `data/design-data.json`
  (то, что было захардкожено в JS-константах: `CAT_META`, `wokBases/Proteins/Sauces`,
  `karmaLevels`, `ADDON_SETS`, зоны доставки). Скрипт **идемпотентный** —
  перезапускать безопасно, данные обновятся, а не задублируются.
- **Дизайн-система** — все токены прототипа перенесены для обеих тем.
  Цвета хранятся как RGB-тройки (`126 85 128`, не `#7e5580`) — это
  обязательное требование Tailwind v3 для модификаторов прозрачности
  (`border-plum/30`), см. комментарий в `globals.css`.

**Фаза 1, часть вторая — страницы и корзина:**

- **Главная** (`/`) — Hero, меню с лентой категорий, акции, карма-клуб, футер.
- **Страница категории** (`/menu/[id]`) — с «визуальным миром» категории
  (фото, японская подпись, слоган из `CategoryMeta`).
- **Страница блюда** (`/product/[slug]`) — галерея, состав, КБЖУ, выбор
  добавок с пересчётом цены, динамические og-теги для превью в мессенджерах.
- **Корзина** — Zustand + localStorage (ключ `gk_cart`), панель со счётчиком
  в шапке, изменение количества, прогресс до бесплатной доставки.
- **Шапка** — навигация, переключатель темы, счётчик корзины.

**Фаза 1, часть третья — заказ:**

- **Чекаут** (`/checkout`) — способ получения, контакты, адрес с определением
  геопозиции, оплата, промокод. Итог **пересчитывается на сервере** при каждом
  изменении: цены блюд, добавок и скидка берутся из базы, а не из браузера.
  В прототипе скидка считалась в JS на клиенте — подменив её в консоли, можно
  было оформить заказ за любую сумму. Здесь клиент присылает только «что и
  сколько», всё остальное решает сервер (`src/server/pricing.ts`).
- **Зоны доставки** (`src/lib/delivery.ts`) — гаверсинус + пять зон, цена
  и порог бесплатной доставки зависят от расстояния. Логика вынесена отдельно
  и покрыта проверкой границ: `npm run check:delivery` (ровно 4 км — ещё первая
  зона, 4.1 — уже вторая; дальше 20 км доставки нет).
- **Страница заказа** (`/order/[number]`) — этапы без обратного отсчёта
  (сознательное решение из прототипа), состав, кнопка «Узнать о заказе»
  на телефон или внешнюю страницу через константу.
- Заказ пишется в базу вместе с позициями, добавками и начислением
  карма-баллов в журнал (`KarmaLedgerEntry`).

**Фаза 1, часть четвёртая — страницы и интерактив:**

- **Отдельные страницы** вместо якорей: `/menu` (весь каталог по категориям),
  `/promotions`, `/karma-club`, плюс уже были `/menu/[id]`, `/product/[slug]`,
  `/checkout`, `/order/[number]`. В шапке активный пункт подсвечивается.
- **Акции стали интерактивными**: кнопка промокода копирует его в буфер
  и сразу применяет к корзине — на чекауте поле уже заполнено. Промокод
  хранится в общем состоянии корзины.
- **Карма-клуб — калькулятор**: два ползунка (средний чек и число заказов
  в месяц) показывают, сколько баллов накопится за три месяца, до какого
  уровня это доведёт и на какую награду хватит.
- **Исправлена вёрстка флагманской акции**: классы раскладки передавались
  в декоративную обёртку `PromoFrame`, а не на контент — из-за этого две
  колонки схлопывались и фото падало под текст.

**Админка, фаза 1 — товары и изображения:**

- `/admin/products` — защищённый список товаров, создание, редактирование и
  удаление. Сессия хранится в подписанной `httpOnly` cookie; middleware
  проверяет JWT для всех административных маршрутов.
- Администраторы не регистрируются через сайт. Первый аккаунт создаётся так:

  ```bash
  npm run create-admin -- admin@example.com 'надёжный-пароль' 'Имя'
  ```

- Картинки загружаются напрямую из браузера в S3-совместимый бакет по
  presigned PUT URL. Для работы нужны `S3_*` и `ADMIN_SESSION_SECRET` из
  `.env.example`; на бакете нужно разрешить CORS для `PUT` с домена админки.
- В `ProductImage.url` сохраняется обычный публичный URL. Старые локальные
  пути `/assets/...` продолжают поддерживаться.

**Админка, фаза 2 — контент и доставка:**

- `/admin/categories` — CRUD категорий и их визуальных метаданных;
  идентификатор категории после создания не меняется, удаление категории с
  товарами блокируется понятным сообщением.
- `/admin/promotions` — CRUD акций, сроки активности, выбор существующего
  товара для изображения или своя загрузка в S3 (приоритетнее), выбор фона
  карточки из фиксированного набора пресетов (не свободный цвет). Промокод
  после создания неизменяем.
- `/admin/promotions/banner` — редакционный блок вверху `/promotions`
  (заголовок, текст, фоновая картинка) — один на весь сайт, без списка и
  создания, только редактирование одной записи.
- `/admin/karma-club` — управление уровнями и наградами клуба. Для уровней
  проверяется, что верхняя граница выше нижней.
- `/admin/delivery-zones` — боевые тарифы доставки с проверкой строго
  возрастающих радиусов. Сохранённые изменения участвуют в расчёте новых
  заказов сразу.
- `/admin/wok-builder` — CRUD основ, белков и соусов конструктора вока.
  Читается напрямую конструктором на сайте и расчётом цены, правки
  применяются сразу; для ID без фото в реестре ассетов показывается
  нейтральная иконка вместо фото.
- `/admin/orders` — очередь активных заказов, история с фильтрами и
  пагинацией, полная read-only карточка заказа и ручное продвижение статуса
  заказа/оплаты. Изменения сразу отражаются в клиентском трекере.
- `/admin/team` — только для роли `OWNER`: список администраторов, создание
  нового (email/пароль/имя/роль `OWNER`/`STAFF`), смена роли, удаление.
  Роль ограничивает доступ только к этой странице — остальная админка
  одинакова для `OWNER` и `STAFF`. Нельзя удалить себя или оставить систему
  без единого `OWNER` (сервер проверяет это при каждой попытке).
  `npm run create-admin -- email пароль 'Имя' [owner|staff]` создаёт первого
  администратора (по умолчанию `owner`) — дальше новых заводят через UI.

**Вход в профиль через Telegram-бота:**

- `/profile` запрашивает четырёхзначный одноразовый код; код хранится только
  как bcrypt-хеш и действует пять минут.
- Сервер ограничивает отправки тремя за десять минут на номер и ввод пятью
  попытками на код. Повторная отправка инвалидирует предыдущий код.
- Код доставляется Telegram-ботом (`TELEGRAM_BOT_TOKEN`), не SMS — бесплатно.
  Бот не может написать первым: для номера без привязки сайт показывает
  deep-link `t.me/<бот>?start=<телефон>` — человек жмёт Start, сайт находит
  это через `getUpdates` (long polling, не вебхук — публичного HTTPS пока
  нет) и сохраняет `TelegramLink` (phone → chatId). Дальше при новых входах
  с этого номера шаг с Start не повторяется, код летит сразу.
- Без `TELEGRAM_BOT_TOKEN` запрос кода вернёт «Вход через Telegram сейчас
  недоступен» — это единственная точка отказа, отдельного dev-режима нет.
- После подтверждения кода сервер выдаёт подписанную `httpOnly` cookie
  (`gk_customer_session`, JWT на `CUSTOMER_SESSION_SECRET`, 90 дней). Все
  действия в профиле (`getProfileData`, `claimReward`, `addAddress`,
  `removeAddress`) берут `userId` только из неё, а не из аргумента — раньше
  `identity.userId` из клиентского `localStorage` передавался напрямую в
  эти server actions, и его можно было подменить в devtools, чтобы увидеть
  или списать чужие баллы. `localStorage` (`gk_identity`) остался только
  для мгновенного UI-решения «показать вход или профиль» без ожидания сети.
- Выход (`Выйти`) очищает и `localStorage`, и cookie.

## Чего ещё нет

Реальная оплата и «выйти со всех устройств» — сейчас одна долгоживущая
(90 дней) сессия на устройство, отозвать конкретную сессию удалённо нельзя.

## Первый запуск

```bash
npm install
cp .env.example .env   # заполнить DATABASE_URL/DIRECT_URL от своего Supabase-проекта
npx prisma generate
npx prisma db push
npm run db:seed
npm run dev
```
